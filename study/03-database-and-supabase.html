Module 03

The Database & Supabase Layer (supabase/)

Understand SQL tables, UUIDs, migrations, Row Level Security, and Kobo pricing.

1. What is a Relational Database?

A relational database stores data inside structured tables (like tabs in Excel). Unlike simple files, relational databases enforce strict types, unique constraints, and relationships between tables using Foreign Keys.

  • Table: The entity (e.g. listings, users).
  • Column: The specific property (e.g. price_annual_kobo, phone_number).
  • Row / Record: One specific real-world entry (e.g. "Standard Executive Self-Contain at Akoka").
  • Primary Key (PK): The unique identity badge of that row (e.g. id UUID PRIMARY KEY).
  • Foreign Key (FK): A link pointing to another table. For example, listings.agent_id points to agent_profiles.id.

2. Why Do We Use UUIDs?

Beginner apps often use auto-incrementing numbers (id = 1, 2, 3). Aroom uses UUIDs (Universally Unique Identifiers) like f1111111-1111-1111-1111-111111111111.

⚠️ The Hexadecimal Rule (Why We Fixed the UUID Error)
A UUID is a 128-bit number formatted as 32 hexadecimal characters separated by hyphens.
Hexadecimal only allows digits 0-9 and letters a-f.

When we previously used dummy IDs like 'u1111111...' (u for user) or 's1111111...' (s for student), PostgreSQL threw:
ERROR: 22P02: invalid input syntax for type uuid: "u1111111-1111-1111-1111-111111111111"

Because u, s, and l are not valid hex numbers! We resolved this by using valid hex letters:
  • c... for Campuses (c is hex 12)
  • a... for Agents (a is hex 10)
  • d... for Users (d is hex 13)
  • b... for Student Profiles (b is hex 11)
  • f... for Listings (f is hex 15)

3. Why Prices Are Stored in Kobo (BIGINT price_annual_kobo)

In listings, you will see prices written as 35000000 for a ₦350,000 room.

Why not store 350000.00 as a decimal or float?
In computer processors, floating point math has rounding errors (e.g., 0.1 + 0.2 = 0.30000000000000004). By storing money as integers in the smallest currency unit (1 Naira = 100 Kobo), our financial math is always 100% exact.

4. The 11 Core Database Tables in Aroom

Table Name Purpose in the Marketplace
campuses Master university data (e.g. UNILAG), boundary coordinates, and institutional email domains.
users Core login credentials, phone numbers, and user types (student, agent, admin).
student_profiles Matriculation numbers, university email, and institution verification status.
agent_profiles Agency names, ID cards, trust tiers (gold, silver, bronze), and response rates.
listings Accommodation listings: title, room type, annual price in Kobo, landmark, and status.
listing_media Photos and videos of properties, including a live camera verification flag.
inquiries Inspection booking requests submitted by students from the Web or WhatsApp.
availability_reports Crowdsourced reports: students report whether an inspected room is still available or taken.
inspection_reviews Post-inspection ratings (1-5 stars), agent punctuality, and property accuracy reviews.
conversation_sessions Saves conversation state for WhatsApp bot triage across multiple messages.
audit_logs Immutable activity log for security, disputes, and trust score changes.

5. Row Level Security (RLS) & Storage

Supabase includes Row Level Security (RLS) directly inside PostgreSQL. Even if a user connects to the database: 

-- Public can view listings:
CREATE POLICY "Public Read Listings" ON listings FOR SELECT USING (true);

-- Agents can only update their own listings:
CREATE POLICY "Agents can update own listings" ON listings FOR UPDATE
USING (agent_id IN (SELECT id FROM agent_profiles WHERE user_id = auth.uid()));
