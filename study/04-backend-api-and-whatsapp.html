Module 04

The Backend API & WhatsApp Bot (backend/)

How Express routes, Clean Architecture services, and WhatsApp conversational triage work.

1. What is an Express REST API?

The backend is written in Node.js using the Express framework. It listens on Port 5000 and defines routes that respond with JSON.

  • GET /api/v1/listings — Search & filter property listings
  • POST /api/v1/inquiries — Book inspection slot (from Web or WhatsApp)
  • PATCH /api/v1/listings/:id/status — Agent single-tap toggle (available ↔ held ↔ taken)
  • POST /api/v1/reports/availability — Student flags whether room is taken
  • POST /api/v1/webhook — Meta WhatsApp Cloud message handler

2. Clean Architecture: Why We Separate Routes from Services

In amateur code, developers often mix database queries, calculation formulas, and HTTP handling in a single file. In Aroom, we separate them: 

HTTP Request ──► [ Route Handler ] ──► [ Domain Service ] ──► [ Database Store ]
                   (Checks inputs)      (Executes logic)       (Saves data)
  • ListingService: Encapsulates multi-parameter search, ensures new listings default to unverified_new, and enforces status transitions.
  • InquiryService: Shared by both the website and WhatsApp! When a student creates an inquiry, this service automatically transitions the listing to held to prevent double bookings.
  • TrustService: Computes agent trust scores (0-100) and reviews crowdsourced availability reports.
  • IdentityService: Checks institutional student email domains (@live.unilag.edu.ng).

3. The WhatsApp Conversational State Machine

The WhatsApp bot is not an unpredictable generic chatbot. It is a structured Finite State Machine (FSM):

stateDiagram-v2 [*] --> START: Student sends message START --> AWAIT_CAMPUS: Bot asks "Which Campus?" AWAIT_CAMPUS --> AWAIT_BUDGET: Student selects UNILAG AWAIT_BUDGET --> SHOW_LISTINGS: Student sets max budget (e.g. ₦350k) SHOW_LISTINGS --> BOOK_INSPECTION: Student picks Listing #1 BOOK_INSPECTION --> [*]: Slot confirmed & agent alerted!
